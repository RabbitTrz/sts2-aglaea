### 2.1 能力图标 Power icon
| 类型 | 尺寸 | 路径 |
|---|---|---|
| 普通图标 | **250 × 250** px | `Aglaea/images/powers/<name>.png` |
| 大图标（hover 详情） | **500 × 500** px | `Aglaea/images/powers/big/<name>.png` |

- 命名规则（`AglaeaPower.CustomPackedIconPath`）：`Id.Entry.RemovePrefix().ToLowerInvariant()`，即去掉 `MOENEGIMOD-` 前缀后整段小写。
  - 例：`TailorSwarmPower` → `tailor_swarm_power.png`；`WeaveLinePower` → `weave_line_power.png`。

### 2.3 卡面 Card art（本次新增）

> 权威依据：`AglaeaCard.cs` 内注释（第 17-49 行）+ 实测本模组现有卡图 + `CardModel.cs` 原版 atlas 路径对比。

**代码内写明的尺寸标准（`AglaeaCard.cs` 注释原文）：**
```
//Image size:
//Normal art: 1000x760 (Using 500x380 should also work, it will simply be scaled.)
//Full art: 606x852

//Smaller variants of card images for efficiency:
//Smaller variant of fullart: 250x350
//Smaller variant of normalart: 250x190
```

| 类型 | 尺寸 | 路径 |
|---|---|---|
| 正式卡面大图（普通卡） | **1000 × 760** px（也可 500×380，自动缩放） | `Aglaea/images/cards/big/<name>.png` |
| 正式卡面大图（全幅卡 full-art） | **606 × 852** px | `Aglaea/images/cards/big/<name>.png` |
| 卡面小图（普通卡，渲染用） | **250 × 190** px | `Aglaea/images/cards/<name>.png` |
| 卡面小图（全幅卡，渲染用） | **250 × 350** px | `Aglaea/images/cards/<name>.png` |

- **命名规则**：`Id.Entry.RemovePrefix().ToLowerInvariant()`，即去掉 `MOENEGIMOD-` 前缀后整段小写。
  - 例：`AglaeaDemigodForm` → `aglaea_demigod_form.png`；`AglaeaDenseRain` → `aglaea_dense_rain.png`。
- **路径映射（`StringExtension.cs`）**：
  - `CardImagePath()` → `{ModId}/images/cards/{name}.png`（小图）
  - `BigCardImagePath()` → `{ModId}/images/cards/big/{name}.png`（大图）
- **透明通道**：普通卡图为 RGB（无 alpha）；power/relic 图标为 RGBA。
- **格式**：PNG（Godot `CompressedTexture2D`，`compress/mode=0` 不压缩、`mipmaps/generate=false`）。

**与原版 STS2 的差异（重要）**：原版卡图**不是独立 png**，而是打包成图集
`atlases/card_atlas.sprites/{卡池}/{id}.tres`（见原版 `CardModel.cs:143`）。
**BaseLib mod 体系用独立 png**（`CustomPortraitPath` 返回 png 路径），所以本模组直接放 png 即可，无需图集。

**当前实现待注意（潜在缺口）**：`AglaeaCard.cs` 中 `CustomPortraitPath`（大图）与
`PortraitPath`（小图）逻辑目前**完全相同**，都指向 `images/cards/` 小图目录；
`BigCardImagePath()` 虽已定义但**尚未被调用**，且 **`images/cards/big/` 目录尚未创建**。
即：卡牌的正式大图（1000×760 等）尚未落地，当前卡面统一为 250×190 占位小图。

## 四、附：powers.json 中 description 与 smartDescription 的区别

代码依据：`PowerModel.cs`（`HoverTips` 属性，约 350-399 行）。

| | description | smartDescription |
|---|---|---|
| 性质 | 静态完整说明 | 动态简短摘要 |
| 变量注入 | 只注入卡牌 DynamicVar，**不自动注入 `{Amount}`** | 自动注入 `{Amount}`、`OwnerName`、`PlayerCount` 等运行时变量 |
| 何时显示 | 无 smartDescription 或 power 不可变时 | `HasSmartDescription && IsMutable` 时优先显示 |
| 典型写法 | `"每层使衣匠伤害+1"` | `"衣匠伤害+{Amount}"` |

一句话总结：`description` 是静态全文，`smartDescription` 是可写 `{Amount}` 等运行时变量的动态简短版，存在且 power 可变时优先顶替 description 显示在 hover 上。标记型 power（`PowerStackType.Single`）无动态数字，可只写 `description`。
